# Data

## Source

UCI Machine Learning Repository, Heart Disease data set,
https://archive.ics.uci.edu/dataset/45/heart+disease, licence CC BY 4.0
(https://creativecommons.org/licenses/by/4.0/). The cohort used here is the
Cleveland processed file `processed.cleveland.data`: 14 comma-separated
columns, no header row, `?` for a missing value. The source documents 303
rows; the adapter reports the count it actually reads next to that figure
(`load_report.rows_read`, `rows_documented`, `row_count_matches_documented`)
rather than assuming it.

Nothing is redistributed in this repository. The user obtains the file and
places it at `DATA_ROOT/processed.cleveland.data`, then passes
`--data-root DIR` or sets `DATA_ROOT`. A missing root or file raises
`DataRootError` naming the file, the dataset page and the download command.

## Columns

| position | name | treatment |
|---|---|---|
| 1 | `age` | numeric |
| 2 | `sex` | numeric code as in the source |
| 3 | `cp` | numeric code as in the source |
| 4 | `trestbps` | numeric |
| 5 | `chol` | numeric |
| 6 | `fbs` | numeric code as in the source |
| 7 | `restecg` | numeric code as in the source |
| 8 | `thalach` | numeric |
| 9 | `exang` | numeric code as in the source |
| 10 | `oldpeak` | numeric |
| 11 | `slope` | numeric code as in the source |
| 12 | `ca` | numeric; carries `?` in the source |
| 13 | `thal` | numeric code as in the source; carries `?` in the source |
| 14 | `num` | target field, integer 0 to 4 |

All 13 attribute columns are passed to the models as floats. Coded columns
are not one-hot encoded; this is a baseline suite and the coding is left as
the source provides it. Adding an encoder is a change to `models.py` and
`docs/method.md`.

## Target mapping

The binary label is

```
label = 1  if num > 0
label = 0  if num == 0
```

`num` is the source's integer field with values 0 to 4. Any other value, or a
missing `num`, is a `SchemaError`; the target is never imputed. The mapping
is implemented once, in `schema.map_target`, and tested.

## Missing values

`?` is the only missing marker. `schema.replace_missing_marker` turns the
exact string `?` (after stripping whitespace) into NaN at load and counts
the cells. Imputation happens inside each cross-validation fold: the
`SimpleImputer` in each pipeline is fitted on that fold's training rows and
applied to its test rows. Nothing about the test rows reaches the imputer's
statistics; `test_imputer_and_scaler_are_fitted_on_training_rows_only`
perturbs the held-out rows and asserts the fitted parameters are unchanged.

## Download command

```
python -m heart_risk_calibration download --data-root /path/to/dir
```

prints the dataset page, the licence and the file URL and exits 2 without
fetching. Only

```
python -m heart_risk_calibration download --data-root /path/to/dir --accept-terms
```

fetches the file, and the command refuses to run when `CI` or
`GITHUB_ACTIONS` is set. The Makefile target is `make download
DATA_ROOT=/path ACCEPT_TERMS=1`. CI never runs it.

## Synthetic fixture (`examples/fixtures/v1`)

Authored synthetic demonstration data. Fictional identifiers. Not derived from
any patient, dataset, or person. Generated by `tools/make_fixtures.py` with
seed `42`, fixture version `v1`.

`synthetic_heart.csv` has 300 rows: `patient_id` (`SYN-P0001` ...), the 13
attribute columns above, and `num` in 0 to 4. Six cells carry `?` (four in
`ca`, two in `thal`) so that the imputer path is exercised. The first lines
are `#` comments stating the provenance.

Each attribute is drawn independently from a simple distribution over the
coded range used by the source file. The positive class is planted: a logit
is formed as a linear function of `age`, `sex`, `cp == 4`, `thalach`,
`oldpeak`, `ca`, `thal == 7` and `exang` with the coefficients recorded in
`fixture_meta.json`, plus Gaussian noise; the label is a Bernoulli draw from
that probability, and positive rows receive a `num` severity in 1 to 4. The
distributions and coefficients were chosen for readability. They are not
fitted to any data and carry no information about any patient. Fixture runs
are recorded with `source_id: synthetic-fixture-v1` and can only run in
`smoke` or `demo` mode.
