# Contributing

## Setup

```
pip install -e .
pip install pytest
make smoke && make test
```

Python 3.10, 3.11 and 3.12 are supported; CI runs all three.

## Ground rules

- No invented numbers. A metric may appear in the README or docs only if a
  script in this repository computed it on the synthetic fixture, and the text
  says so.
- No patient data is committed. The fixture is synthetic, generated by
  `tools/make_fixtures.py`, and labelled as such. `processed.cleveland.data`
  and `*.pkl` are ignored by git.
- Library code raises; the CLI prints. No `print` in `src/`.
- Preprocessing and selection stay inside the outer-training rows. A change
  to `training.py` must keep
  `test_imputer_and_scaler_are_fitted_on_training_rows_only` and
  `test_threshold_never_uses_test_labels` passing.
- Synthetic sources run in `smoke` or `demo` mode only; `experiment` is for
  user-supplied data.
- CLI help and demo output must not contain the strings `recommend` or
  `diagnos`; a test enforces this. This repository is not a clinical tool.
- No em dashes in prose. No marketing adjectives.

## Changing the protocol or the models

1. Edit `configs/eval.yaml` or `configs/model.yaml` (and the `_smoke`
   variants if the smoke path is affected); document the change in
   `docs/method.md` and `docs/evaluation.md`.
2. Add or adjust tests.
3. Regenerate the fixture if the generator changed
   (`python tools/make_fixtures.py --seed 42 --out examples/fixtures/v1`) and
   rerun `make demo` so the committed outputs and the README table match.
4. Run `python -m pytest -q` and paste the summary line into
   `docs/evaluation.md`.

## Pull requests

Keep changes small and cohesive. State which behaviour changed and which test
proves it.
